SUPABASE AUTHENTICATION, FEEDBACK, AND DISH SUGGESTIONS

All website accounts, public feedback, and dish suggestions use Supabase.
The browser uses the Supabase project URL and public anon/publishable key.
Never put a service_role key or secret key in this website.

1. Create or open the Supabase project and run the complete SQL script in
   supabase/website-tables.sql using the Supabase SQL Editor. The script
   creates the feedback, suggestion, and administrator tables, row-level
   security policies, grants, and the feedback realtime publication.

2. Open Project Settings > API and copy the Project URL and public anon or
   publishable key into Javascript/supabase-config.js as url and anonKey.
   The URL must be the Supabase project URL ending in .supabase.co, not the
   website's GitHub Pages address. The public key is safe for browser use
   when row-level security is enabled.

3. Enable email/password sign-in in Authentication > Providers. Configure
   the deployed HTTPS website as the Site URL and add it to the allowed
   redirect URLs, including
   https://renz176.github.io/Tahak-sa-Panlasa-website/login.html. If email
   confirmation is enabled, visitors must confirm their address before
   signing in. Password recovery returns to this login page so users can set
   a new password.

4. To grant administrator access, create an account using Login, then copy
   its user UUID from Authentication > Users. Run the following in SQL
   Editor after replacing the example UUID:

   insert into public.website_admins (user_id)
   values ('PASTE-THE-ADMIN-USER-UUID-HERE')
   on conflict (user_id) do nothing;

   Administrator records cannot be created or changed from the website.
   The same administrator role controls feedback removal and suggestion
   review. Revoke access by deleting the user's row from website_admins.

5. Enable Realtime for website_feedback if it is not already listed in the
   supabase_realtime publication. The SQL script adds it when possible.
   Public feedback updates live; dish suggestions are visible only to admins.
   Approved suggestions still need to be reviewed and added to the local
   catalog in Javascript/script.js.

The public anon/publishable key is not an admin credential. Row-level
security policies enforce all public and administrator permissions. Do not
disable RLS. Back up existing tables before applying schema changes; the
script preserves existing rows but legacy tables with different columns or
invalid data may need a schema/data migration first.

Accounts and records in other services are not migrated automatically.
